## The governing reality (read before scoping anything)

The audit's central finding: **the P0 substrate is ~70% already built, and the work is almost never "build from scratch."** It is *wire the orphaned thing*, *consolidate the fragmented thing*, *stop hiding the honest thing*. Concretely:

- The **real SD-JWT engine** (salted disclosures, ES256, Merkle predicate proofs, audience/nonce verification) exists in `apps/api/backend/src/services/sd-jwt/` and `services/credentials/` — but is flag-gated off and its two composer UIs are orphaned scaffolds.
- The **real verification transcript** (event hashes → Merkle root → inclusion, with `Root MISMATCH` failure localization) is already computed by `GET /api/audit/proof/:eventHash` (`apps/api/backend/src/routes/audit.ts:58-77`) — and consumed by nothing. `AuditProofViewer.tsx` is an orphaned static mock in the *old* design system.
- **Live source-check narration** already ships twice (`LiveNpiResult.tsx`, `OnboardingReadiness.tsx`) — but on blind timers, not real per-source resolution, and with a reduced-motion-violating `animate-spin`.
- The **canonical status vocabulary** (checked/gated/stale/unknown/…) lives cleanly in `packages/trust-state/sourceCoverage.ts` — but ~8 fragmented enums render it across the UI, and **`revoked` exists in no UI status enum** (it silently collapses to "Unavailable"; on `/verify` revoked credentials are *filtered out entirely*).
- **Accept already captures an immutable `DecisionTrustSnapshot`** with per-source coverage — but never links it to a content-addressed artifact, so re-share diff is feasible coarsely today and needs one small persistence prerequisite for per-credential fidelity.

So: **every wave below is scoped as extend/wire/consolidate, with the real anchors named.** Two consequences that must be respected everywhere:

1. **A dense test/CI guard web.** See [Appendix A](#appendix-a--guardrails-every-wave-must-keep-green). Truth-contract vitest suites and two CI copy gates will fail-closed on careless copy or vocabulary changes. This is a feature — it's the truth contract enforced — not an obstacle.
2. **The copy-tension landmine.** `apps/web/__tests__/passport-copy-truth.test.ts` **bans the literal strings** `SD-JWT`, `wallet`, `Merkle audit trail`, `tamper-proof`, `real-time` (etc.) from `app/passport/page.tsx`, and `packages/truth-enforcement/src/claim-policy.ts` makes "cryptographically verified" **capability-gated**. Any pattern that wants to *name* the cryptography must live **off** the passport page and use honest, non-banned phrasing backed by a real active signing path. This single tension decides where W6 (disclosure composer) can render.

## W1 — Provenance Chip System v2 `[T1 · T2 · T3 · T6]`  ⭐ foundation

**Current state (anchors):**
- Canonical vocabulary already exists: `packages/trust-state/sourceCoverage.ts` `CanonicalSourceCoverageState` = checked/stale/pending/gated/unavailable/accessRequired/reviewRequired/notDecisionGrade/previewOnly. **Anchor all chips to this.**
- Reusable shells: `matcha-zen.css .mz-chip/.mz-gl` (dot+word+mono, states ok/watch/unknown/p0); `design-system/components/TruthStateChip.tsx` (a11y + banned-string contract, but **timestamp is `sr-only`** — the core gap); `design-system/components/IdentityField.tsx:64-71` (a real mono `Source` line); `components/passport/PassportWallet.tsx:172-205` `AuthorityRow` (the "title · status · source · checkedAt · confidence · freshness" contract to lift); `styles/trust-register.css .trust-register-dashed` (self-attested band); `components/vital/StateChip.tsx` (already has a `self_attested` state).
- **The revoked gap:** `revoked` is in **no** UI status enum; `lib/trust/status-language.ts:236` maps `REVOKED → 'Unavailable'` and red is owned by `adverse`. Revocation lifecycle data is real (`apps/api/backend/src/services/revocationService.ts`, `VerificationArtifact.revokedAt`, status-list bit) but never surfaces as a distinct fail-closed UI state.

**Scope:**
- [ ] Promote one chip component (extend `TruthStateChip` or a new `ProvenanceChip` in `design-system/`) that renders the **visible** mono `source · timestamp` line (not `sr-only`) — driven by `CanonicalSourceCoverage.provenance` (sourceUrl/checkedAt).
- [ ] Add a first-class **`revoked`** state with its own register (red, fail-closed treatment), wired from the revocation lifecycle up through `status-language.ts` — distinct from `adverse`/`unavailable`.
- [ ] Formalize the dashed **self-attested** band as a chip variant (fold in `trust-register.css` + `vital/StateChip` self_attested).
- [ ] Pick the canonical vocabulary (the trust-state words) and map the ~8 fragmented enums onto it **without changing the pinned display labels** the tests assert.
- [ ] Ship a legend/story documenting the final six-state system.

**Real vs demo:** fully real — data exists for all six states.
**Guards to keep green (critical):** `apps/web/__tests__/truth-state-chip.test.tsx` (banned strings + exact `TRUTH_STATE_ORDER` + `sr-only <time>` behavior — **you're changing the timestamp behavior, so update this test deliberately**), `trust-status-language.test.ts` (exact label map incl. `verified→'Source-backed'`, `clear→'Checked'`), `banned-verified-label.test.ts`.

**Current state (anchors):**

**Scope:**
- [ ] Add a single regulator-anchored window config (NCQA 120/90-day + monthly/30-day sweep SLAs per source id); make one freshness engine authoritative and route the others to it.
- [ ] Wire `FreshnessIndicator` to real `expiresAt`; add cadence rows (`last swept · next due`), an expiry-horizon strip, and the 90/60/30 escalation ladder.
- [ ] Consequence-naming stale copy on holder + employer surfaces; render via the W1 stale chip.

**Real vs demo:** real where `expiresAt`/SLAs exist; where a source has no real cadence, show `unknown`, not a fabricated window.
**Guards to keep green:** `passport-readiness-snapshot` tests, `trust-source-coverage.test.tsx`, `FreshnessIndicator` consumers; do not introduce a bare "Verified".

## W5 — Verification transcript `[A2 · A3 · A5]`

**Goal:** Render proof-checking as a stepwise mono transcript (event hashes → chain → Merkle root → inclusion verified) that **locates the exact break and fails closed** on tamper; show pending→anchored states.

**Current state (anchors):**
- **The transcript is already computed server-side:** `apps/api/backend/src/routes/audit.ts` `GET /api/audit/proof/:eventHash` returns `verificationSteps[]` with `Start: leaf = …` → `Level N: H(a||b) = …` → `Root matches ✓` **or** `Root MISMATCH — expected …` (`audit.ts:58-77`), over the real `AuditEvent` Merkle batch (`services/ledger/merkleBatcher.ts`). **Consumed by nothing** — no web proxy under `apps/web/app/api/audit`.
- `apps/web/components/verifier/AuditProofViewer.tsx` is **orphaned, fully static, old design system** (hardcoded fake hashes, `bg-slate-*`/framer-motion). **Replace it — do not extend it.**
- Anchoring: `merkleBatcher` flips `AuditEvent.anchored` boolean + sets `merkleRoot` (real); the on-chain write is *simulated* (`workers/anchorWorker.ts:30-35`). **`AuditEvent` has no `anchoredAt` column** — the proof's `anchoredAt` is really `createdAt`.

**Scope:**
- [ ] Add a Next proxy under `apps/web/app/api/audit/...` mirroring the existing trust-state/receipts proxies.
- [ ] Build a new `.mz` transcript component that renders the real `verificationSteps` + `proof[]` + `merkleRoot`, with a line-by-line reveal (W0 motion) and the located `MISMATCH` failure state (fail-closed).
- [ ] Retire/replace `AuditProofViewer.tsx`.
- [ ] Pending→anchored: render the real `anchored` boolean honestly ("anchored in batch" vs "pending"). **Dual-timestamp is a deferred sub-task** (needs an `AuditEvent.anchoredAt` schema column + set it in `merkleBatcher` — see [Appendix B](#appendix-b--p1p2-backlog-surfaced-by-the-audit)).

**Real vs demo — be explicit in copy:**
- **Real:** event hashes, Merkle root, inclusion proof + steps, root MATCH/MISMATCH localization, pending-vs-anchored boolean.
- **Not yet real (don't imply otherwise):** the "chain valid" step (no event-hash *chain* verification in `audit.ts` — hash-chaining lives only in `TrustLedgerEntry`), the distinct anchor timestamp, and the on-chain confirmation (simulated).
**Guards to keep green:** `check-public-claims.ts` (transcript copy), `services/audit/__tests__/auditBundleProof.test.ts`; add a component test for the transcript strings.

## W6 — Re-share diff + watch-passport `[E5 · E6]`

**Goal:** When a clinician re-shares to an employer who already accepted, lead with the **delta** ("2 checks refreshed, 1 new license, nothing revoked since 2026-04-02"); optionally let the employer **watch** the accepted passport for stale/revoked/refresh.

**Current state (anchors):**
- Accept persists an immutable `DecisionTrustSnapshot` (`apps/api/backend/src/services/entity/employerReviewActions.ts:103-284`, stored in the acceptance `AuditEvent.metadata`) carrying **`sourceCoverageSummary`** (`Record<CanonicalSourceCoverageState, sourceId[]>`), per-domain truth statuses, exclusion status, credential counts, `lastCheckedAt`. → **A coarse "N refreshed / nothing revoked / new coverage" diff is computable today.**
- **The fidelity gap:** `EmployerAcceptance.artifactId` is hardcoded `null` and the request `bundleId` is dropped (`employerReviewActions.ts:903-917`), so the acceptance points at no content-addressed snapshot. Per-credential fidelity ("1 new license") needs a snapshot ref. The content-addressed `ReadinessSnapshot` (`schema.prisma:753`, `contentHash`, revocation-aware) already exists — it's just not linked.
- Watch substrate is complete: `model Watchlist` (PROVIDER target = NPI), `model WatchlistHit` (staleness/degradation/revocation feeders), `services/identity/watchtowerStore.ts createWatchlist`. **Nothing wires an acceptance → a watchlist.**
- **Landmine:** `employerReviewActions.ts` is `@ts-nocheck` and org falls back to `employerId` silently (L910-911).

**Scope — split into two:**

Optional: offer "watch this passport" on accept (wire `watchtowerStore.createWatchlist` for the org; no new infra).

**Real vs demo:** real — both snapshots are content-addressed and revocation-aware.
**Guards to keep green:** `employerReviewActions.test.ts` (asserts `employerAcceptance.create` shape/args — W6a changes this deliberately), `readinessSnapshot.test.ts`, `employer-review-*.test.ts(x)`, `acceptanceStartGuards.test.ts`.
**Size:** W6a S, W6b M.
