## Blockers

### BLOCKER 1 — Kaiser Permanente listed as real employer without demo disclaimer

The /employers page shows "Kaiser Permanente Northern California" as a "Directory listed" employer with:

- "Trust score 97"
- "Verified since 2021-03-01"
- "Actively hiring"
- "38 open roles" (from seed data in `employerCatalog.ts`)

This is **hardcoded seed data**, not a real partnership. The /explore page correctly shows a "Demo data" banner. The /employers page has **no equivalent disclaimer**.

The other 4 seed employers (Bay Area Cardiac Group, MindBridge Health, Sacramento Medical Center, Northwest Locums Alliance) are fictional names — lower risk. But using a real Fortune 500 health system's name with fabricated trust scores and hiring status, on a public-facing page, without a demo label, is a **material overclaim** and potential trademark concern.

**Fix:** Add the same "Demo data" banner used on /explore to /employers, OR replace Kaiser's real name with a fictional equivalent in the seed catalog.

### BLOCKER 2 — /developers returns 401 (Vercel deployment protection)

The /developers route returns a Vercel SSO 401 on the preview deployment. All other routes (/, /explore, /interview, /employers) render correctly via the same Vercel auth-bypass tool.

The app's middleware lists `/developers` as a public route (in `roles.ts` line 83 and `publicSurfaceRoutes.ts` line 8). Both navbars link to it. This means a user clicking "Developers" in the nav hits a Vercel auth wall — broken UX on the preview.

**Investigation needed:** Confirm whether this is a Vercel deployment protection config issue (e.g., a redirect pattern or function route that triggers protection) or an app-side middleware ordering bug. If this PR is intended to ship the public site, /developers must render for unauthenticated visitors.

## Follow-ups (non-blocking, post-merge)

1. **PlatformVisionSection mixes built and aspirational without labeling.** "Free Specialty Job Board," "MATCHA — AI Career Matching," and "Clinic Capacity Intelligence" are presented as platform pillars alongside "Cryptographic PSV" and "Universal Clinical Identity" (which have real code behind them). A reader could reasonably think all five exist today. Consider adding a "Roadmap" or "Coming" tag to pillars 02/03/04. Low urgency — it's far below the fold and labeled "The Platform."

2. **"What's already built & working" section claims.** "HIPAA-compliant audit ledger with continuous license monitoring" — "continuous" may overclaim if monitoring cadence varies by source (daily to quarterly). Consider "ongoing" or "periodic." Similarly, "Employer acceptance flow — review and accept verified packets" uses "verified" where the rest of the site carefully says "source-backed."

3. **"live roles" on /explore sidebar.** The bottom-of-page CTA says "VitalCV will show which live roles align with your current readiness state." The page already has a demo-data banner at the top. "Live" contradicts "demo." Consider "current roles" for consistency with /employers.

4. **Market stats need citations eventually.** "$4.2B market," "6.8M workers," "45-90 days," "$9K/day" are all defensible industry figures but have no footnotes. Not a launch blocker but important before any investor or press-facing use of this page.

5. **/onboarding route not audited.** The homepage CTA "Preview my fit" links to /onboarding. This route was not in scope for this audit. Should be verified separately.
