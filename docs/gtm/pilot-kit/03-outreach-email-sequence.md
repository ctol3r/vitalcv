## Touch 3 — Value Add (Day 9–10)

**Subject:** What a credentialing "day zero" packet actually contains

Hi [First Name],

I've been getting questions about what the VitalCV evidence packet actually shows, so I wanted to be specific.

When your team enters an NPI, we return:

- **Identity:** NPPES NPI registry fields — name, specialty taxonomy, enumeration date. This confirms identity, not license status; licensure is a separate state-board lane.
- **Federal exclusions:** OIG LEIE posture against our latest available source release. Not a real-time feed — we record the release date used for each check.
- **Medicare enrollment:** PECOS public enrollment posture. Same approach — source-date recorded per check.
- **State licensure:** One configured state-board lane where public API or institutional access is available.

Everything packages into a proof pack (JSON / PDF / ZIP) with an audit event before it leaves the platform. Your credentialing team gets a structured artifact, not a dashboard with no paper trail.

We don't check NPDB, DEA, ABMS, or CAQH in the current pilot scope — I'd rather be clear about that than oversell what's in the box.

Happy to walk through a live example if that would be useful. 15 minutes?

Best,
Chris
