03

Quiet status system · border semantics · no color fills

borders signal · color does not · always

Status is communicated through border style and weight — not through background color fills. Color is reserved for the print/accessibility override only. This ensures status reads identically in monochrome print, low-contrast displays, and screen readers. The border is the signal. Opacity is never the signal.

Verified · confirmed
Verified
Subject Anchored
Solid border · solid dot. Source responded within SLO. Claim is current. Ownership is bound.

Never use green background fill on a verified row — the border carries the meaning.
Pending · in progress
Pending
Pending In review
Dotted border · hollow dot. Verification initiated, result not yet committed. Receipt written; anchor batch not yet closed.

Never use amber/yellow fill — dotted border already encodes transience.
Degraded · stale · source gap
Source degraded
Stale Source gap
Dashed border · dashed-ring dot. Source was unreachable or returned outside SLO. Last known value shown with explicit age.

Never use reduced opacity to signal stale — opacity looks like "secondary", not "uncertain".
Unknown · not yet checked
Not checked
Not checked Unbound
Thin soft border · muted dot. No verification attempted or no result available. The absence of a check is itself an explicit state, never invisible.

Never render empty — always show "not checked" explicitly.
04

Interruption + recovery · five operational states

left border encodes operational health · always

The left border of every operational row and card encodes its health state. A reviewer scanning a surface can assess continuity by border texture alone — no color reading required. Transitions between states are shown, never hidden. Recovery is an explicit state, not a silent return to normal.

Implementation guidance · Claude Code · binding rules

component decisions · forbidden patterns · token map

These rules are binding on every component built for the VitalCV progression arc. They compress into the following implementation directives. Where a rule conflicts with a UI pattern convention, the rule wins.

Typography & FontGeist + Geist Mono · two families · no exceptions
Fonts
Import Geist weights 300–700 and Geist Mono weights 400–600. No system-ui fallback as primary. No Inter, no Roboto.
Sans usage
Geist for all prose, headings, button labels, body copy. always sentence-case for body.
Mono usage
Geist Mono for all labels, IDs, timestamps, hashes, status tokens, counts, percentages. always uppercase + letter-spacing for labels.
Forbidden
italic for UI elements · bold for entire paragraphs · decorative font weights
Color & Statusink scale · no fills for status · borders carry meaning
Color tokens
Use --ink-* scale only (0–950 + paper). Status colors --s-verified, --s-pending, --s-degraded used in text and left-borders only — never as background fills.
Status signaling
Border style encodes state: solid = verified, dotted = pending, dashed = degraded. always pair border style with a chip label.
Forbidden
green/amber/red background fills · opacity to signal stale · gradient backgrounds · glow or shadow for emphasis
Density & Spacingcompress ruthlessly · reveal on demand
Default tier
All surfaces default to Tier 1 (30-second review). Chain, run_id, source URLs hidden behind expand interaction or explicit Tier 3 surface.
Row density
Operational rows: 12–14px padding top/bottom. Card padding: 16–22px. Never add decoration between rows — rule lines only (1px dashed var(--rule-soft)).
Forbidden
big-number KPI cards · progress rings or doughnut charts · dashboard grid layouts · sparklines
Motion & Animationrestrained · purposeful · zero spectacle
Transitions
State transitions: 150ms ease for color/border, 200ms ease-out for height/reveal. No spring physics. No stagger animations.
Loading states
Skeleton rows with 1px dashed var(--rule) border. No spinning loaders. No pulse animations on content elements.
Pulse indicator
One permitted use: the op-bar live indicator dot. Max 1 pulsing element per page. opacity: 0.35 → 1 over 2.4s, ease-in-out. Nowhere else.
Forbidden
entrance animations on data rows · confetti or success states · parallax · lottie animations
Terminology Compressionplain operational language · no crypto vocabulary
Replace
cryptographic anchor → record committed · DID hash → identifier (where context makes type clear) · blockchain → never used · smart contract → never used
Retain
run_id, checked_at, replay, chain — these have operational meaning; they stay in Tier 3 surfaces only. Body copy uses plain language equivalents.
Replay vocabulary
In body copy: "this record can be re-verified later without re-querying the source." Replay/anchor language reserved for Tier 2+ and implementation docs only.
Forbidden
VC 2.0 · OpenID4VCI · W3C DID as trust signals in UI · audit-ready as marketing copy · zero-knowledge · immutable
Component Inventory · required primitivesbuild these first · everything else extends them
<TrustChip>
variant: state | tier | ownership | replay. tone: solid | outline | dashed | dotted. Mono 9.5px · uppercase · ink-900 always.
<CheckedAt>
Two-line stack. Top: mono 12px UTC tabular-nums. Bottom: mono 9px relative · uppercase. Stale variant: bottom line in s-degraded ink.
<IdRender>
Mono 11px · ink-900 · ink-50 fill · 1px rule border · ellipsis between first 4 and last 4 chars. Full string on hover/focus. Same render for all hashes, NPIs, DIDs.
<ChainStrip>
Horizontal. Tokens connected by ← arrows (ink-400). Current head: ink-900 fill, white text. Prior: ink-50 fill. Single reusable component across all surfaces.
<FreshnessBar>
2px height. Fill = SLO percentage consumed. Stale: fill stops at last known position. No animation. Source name (mono 9.5px) left, age (mono 9px) right.
<VerdictRow>
Single line. ink-900 verdict token · body note · right-anchored audit timestamp. No card shadow. No colored background. Border encodes result.
<DeployPanel>
Go / Hold verdict only. Scan strip (data values) + detail (check list) + verdict footer. No KPI cards. Max 5 scan cells. One verdict pill.
