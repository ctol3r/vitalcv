§1 · Verifier path Decision tree
Q How does the verifier confirm a receipt was issued by VitalCV? Decision
Branch A · Accepted Current path
ES256 issuer / JWKS + ES256 verifier
issuer · sign(ES256) → JWKS · pubkey → verifier · verify(ES256)
  • ·Asymmetric: only the issuer holds the signing key.
  • ·JWKS is the integration surface for downstream verifiers.
  • ·Key rotation handled at the JWKS layer, not in clients.
Reason · trust boundary held at the issuer
Branch B · Rejected Not accepted
HS256 / shared-secret verifier
issuer · hmac(secret) → verifier · hmac(secret)
  • ·Symmetric: every verifier must hold the signing secret.
  • ·Any verifier compromise compromises issuance.
  • ·No clean rotation story across third-party verifiers.
Reason · trust boundary leaks to every verifier
§2 · Caution Read before approving
