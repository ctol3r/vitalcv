04

Trust tier ladder

tier is a property of the source, not of us
T1Self-attest
Holder asserts
Holder claims, no third-party source. Useful as context. Never sufficient for privileging alone.
T2Third-party
Directory or specialty board
Non-authoritative lookup confirms the claim. Probative, not definitive. Pair with T3 when possible.
T3Authoritative
Licensing or regulatory body
The body of record confirms the claim live. Sufficient for most credentialing decisions.
T4Issuer-signed
Source issues a signed VC
Source itself signs over the claim. Verifiable offline against the source’s own DID. Strongest form.
05

States that look similar · meanings that differ

disambiguation
Ownership · subject vs holder vs delegate
Subject Holder Delegate
Subject — same identity holds and is described. Holder — someone holds a credential about themselves but cannot prove subject-binding (rare, transitional). Delegate — an authorized third party (employer, registrar) supplies the claim on the subject’s behalf.
Replay · logged vs anchored vs pending
Anchored Logged Pending anchor
Anchored — receipt chained & RFC 3161 timestamped, replayable months later. Logged — chained in the receipt ledger but no external anchor yet. Pending anchor — backlog or upstream TSA degraded; will anchor at next window.
Signed · signed vs unsigned vs revoked
Signed Unsigned Revoked
Signed — issuer signature present, verifiable against did:web. Unsigned — row carries no issuer signature (holder self-attest, or surface-only). Revoked — signature was valid; Status List 2021 entry now flips the bit. The signature didn’t break — the world changed.
checked_at vs issued_at vs valid_from
checked_at issued_at valid_from
checked_at — when this run consulted the source. The freshness signal. issued_at — when the original credential was issued. valid_from — when the underlying right took effect. A row may be freshly checked yet describe a privilege that began years ago.
run_id stability · same run vs new run
run · 7a2c…b8d3 run · 9d11…3e4a
Same run_id across rows — they were evaluated together, with consistent source state. Different run_id — the row was re-fetched separately; do not compare timestamps without comparing runs. Refresh rotates the run_id even if nothing changed.
Tier strength vs lane verdict
T3Authoritative Verified
Tier is the strength of the source — fixed for that registry. Verdict is the state of this particular check — verified, expired, revoked, unknown. A T3 source can return an unknown verdict; a T1 source can return a verified one. Never collapse the two.
