Product design direction v1.0 · D57

The calm source-of-truth layer between fragmented credentialing systems.

VitalCV is trust infrastructure for healthcare credentialing. It must feel honest, evidence-bounded, and institution-review-aware — and look like something a chief medical officer would trust on first glance. This document defines the visual language, component set, screen architecture, and feature direction to move from limited-pass degraded surface to a state-of-the-art product.

01

Visual North Star

Feeling · Tone · First five seconds

If a chief credentialing officer opens a passport in a hallway between meetings, they should read three things in five seconds: what is true today, what is sourced, what still needs them to decide. The screen should feel like a printed document signed by a system — not a SaaS dashboard.

What VitalCV should feel likedo

Paper, not glass. Warm off-white substrate, near-black ink, hairline rules. The page reads like an issued document — quiet, dense where it matters, generous where it doesn't.

Evidence first, action second. Every field carries its source inline; the primary action only appears after the evidence is legible.

Quiet precision. Tabular numerics, monospace metadata, deliberate whitespace, a single accent. Nothing pulses, nothing animates without cause.

System-side calm. Gaps are gray and labeled — never red. The product never sounds an alarm about a person.

What it must not feel likedon't

Not a hospital intranet. No teal gradients, no clipart caduceus, no 2004 portal chrome.

Not a fintech dashboard. No vanity charts, no green-up-arrow trust scores, no leaderboard energy.

Not crypto theater. No "chain of trust" animations, no node-graph visuals, no certificate seals.

Not generic SaaS. No gradient blob hero, no oversized rounded cards, no fake live counters, no glassmorphism.

First 5 seconds

User reads "NPPES directory record · retrieved 4h ago" beside the clinician's name and understands: sourced presence, not a credentialing verdict.

First 30 seconds

User scans the five-row legend, locates the institution-review boundary, and identifies the single next step. No scrolling required.

First 5 minutes

User opens the Receipt Drawer, sees field-level provenance, exports a Demo Packet. Confidence is earned through transparency, not asserted by chrome.

02

Design Principles

Ten rules · Apply on every screen
P · 01

Evidence before action.

The primary CTA never appears above the sourced fields. Read first, decide second.

P · 02

One primary action per screen.

One ink-black button. Everything else is a link or a ghost. Hierarchy is moral, not visual.

P · 03

Source state is always visible.

Every fact carries source · timestamp · state inline. Tooltips are never the only carrier of truth.

P · 04

System gaps are neutral, not alarming.

Unavailable, gated, not-connected = muted grays and ambers. Red is reserved for true clinician-side adverse findings, which we do not yet surface.

P · 05

Proof details are expandable, never noisy.

The Receipt Drawer holds raw payload, signature, retrieval log. The page surface stays calm.

P · 06

Institution review is always present, quietly.

A visible rail or panel reminds the viewer that this passport is read input to institutional judgment — not the judgment itself.

P · 07

NPI is the front door.

Lookup, not sign-up. The homepage has a number field and a verb — "Look up an NPI" — before anything else.

P · 08

Roles get doors, not modes.

Verifier · Clinician · Employer · Issuer each enter through a labeled door on the homepage. No role-picker modal.

P · 09

Auth gates explain themselves.

Sign-in tells the user what unlocking buys (live event stream, operator tools) before asking for credentials.

P · 10

Receipts beat copy.

Where a marketing line would say "verified," show a row from the connector matrix instead. Show, don't claim.

Surface rules

Radius

2 px — buttons, chips, inputs. 0 px — cards, tables, full-bleed surfaces. Documents do not have rounded corners; UI affordances do, barely.

Borders

1 px hairline in --rule for internal divisions. 1 px ink-900 for the outer edge of a document-like card. 1 px dashed reserved for advisory or gate notices.

Shadow

One value only. 0 1px 0 rgba(15,14,12,.04), 0 0 0 1px rgba(15,14,12,.04). Used sparingly to lift a single critical card. No drop shadows on chips, buttons, or chips.

Interaction Design

Hover · loading · gated · keyboard

Motion is reserved for confirming reality, never performing it. Every interaction clarifies state, signals a transition, or exposes receipts. Nothing animates as decoration.

Hover · focus · active

Buttons darken 1 ink-step on hover (no scale, no shadow expand). 1px translate-y on active. Focus = 2px outline in --accent, 2px offset.

Links get a 1px underline in --ink-300 with 3px offset on hover. No color change.

Source rows reveal a "Receipt →" affordance on hover and focus-within. Row background lifts one ink step.

Loading

No skeletons. Skeletons say "data is coming." VitalCV often has no payload, so a skeleton lies. Use a 1-line monospace state row: NPPES · reading · 0.6s.

Lookup uses an in-button 2px progress bar across the bottom edge; never a full-page spinner.

If a read exceeds 3s, the row swaps to a "temporarily unavailable" chip with retry copy.

Degraded · source unavailable

Field-level. Row keeps its label and source column. Value reads "No reading." in ink-500 with one-line reason.

Connector-level. Same surface, chip is "connector not live," copy distinguishes never-wired vs. transient.

Page-level. If zero reads succeed, the gate-notice block at the top explains "system condition, not clinician finding."

Sign-in required / SSE blocked

Public surface remains public. The auth gate is an in-context dashed-border block, not a redirect. Sign-in is a verb the user chooses.

SSE down when signed-in. Shell renders. Banner: "Live event stream unavailable · history readable." No sign-in loop.

Receipt Drawer interactions

Slides in from right (200ms ease-out, no overshoot). Esc closes. ⌘C copies the highlighted payload section. Body scroll is locked while open.

Width: 480px desktop · full-bleed sheet on mobile (slides up). Backdrop is a 1px ink-300 tint, not a black overlay.

Role switching

No global role-picker. Roles enter through homepage doors. Once inside, the URL carries the role; a small monospace breadcrumb shows employer · review · npi 1699264564.

Switching roles = back to /. Cheaper than a modal, more honest about state.

Keyboard & focus

⌘K opens the global NPI lookup overlay from any route. Tab order follows DOM. All chips are focusable with Enter = "open receipt for this state."

Skip-to-content link on every page. Focus rings never suppressed.

Mobile

Passport rows collapse to stacked blocks: label → value → source → chip. The 5-row legend becomes a horizontally-scrolling rail. CTA strip sticky at the bottom.

No hover affordances; long-press on a chip opens the Receipt Drawer as a bottom sheet.

Accessibility

WCAG AA throughout: ink-700 on paper meets 7:1; chip text passes 4.5:1 against tinted ground. Each truth-state has a glyph in addition to color — never color-only.

Screen-reader copy spells the state ("connector not live, system-side") so meaning carries without sight.

Final Design Call

Status · scope · cost of waiting
Design status
Ready to build
Wave
D57 · Calm Source-of-Truth
Window
Ship Wave D57 in one sprint without backend dependency. D58 and D59 unlock as connectors come online.

The thesis. VitalCV is not a credentialing decision — it is the calm source-of-truth layer between fragmented systems. The visual language must carry that thesis in five seconds, before any marketing copy lands.

What this direction commits to. Paper substrate, near-black ink, single restrained accent. A six-state truth-chip family with glyphs and copy. Source-row canonical layout on every passport field. Per-field provenance instead of bare "verified." Institution-review boundary always visible, always quiet. Receipts beat claims.

What it commits against. No bare "Verified." No "cleared / approved / accepted." No HIPAA / SOC 2 / NCQA certification claims. No skeleton-only degraded states. No red on system-side gaps. No crypto theater. No fake live motion. No SaaS hero gradient.

Cost of not shipping D57. The product remains a limited-pass degraded surface where source unavailability still reads, to a hurried viewer, as clinician failure. That is the only real risk left in the build, and it is a design risk.

Recommendation. Adopt this direction as canon, freeze tokens, extract the chip + source-row family first, ship Wave D57 against the existing routes. The product can feel exceptional today without any new connector going live tomorrow.
