Attention model · four zones · one reading direction

Z → A → B → C → D · never compete

Every screen is divided into four zones. The eye enters at Zone A. A reviewer should be able to form a judgment at Zone A alone and exit. Zones B, C, and D exist to answer follow-up questions — they never compete with Zone A for attention. Zone A is never empty. Zone D is never prominent.

02

Progressive disclosure · four tiers · controlled reveal

default to Tier 1 · reveal on explicit intent

Information reveals in response to intent, not by default. A reviewer who needs only a verdict gets the verdict. A reviewer conducting an audit gets the full chain. The surface never forces the audit view on the reviewer who needs the verdict. Each tier is a gate — opened by the reviewer, not by the system.

Quiet status language · plain English · no engineering vocabulary

institutional readers · not infrastructure engineers

Every status message is written for an institutional reviewer, not a systems engineer. The infrastructure that produced the status is invisible. The operational meaning is clear. Messages are stated once, plainly, and without alarm unless alarm is warranted.

04

Action hierarchy · four levels · maximum three visible

one dominant · two supporting · no more

Every screen has one primary action. It is always the most important thing a reviewer can do right now. Secondary and ghost actions exist to support it — never to compete. Destructive actions have no button chrome. If three actions feel like too many, remove one.

Level 1 · Primary
ink-900 fill · white text · mono uppercase. One per screen. Answers "what should happen next?" Never disabled — if no action is available, hide it entirely. Never two primary buttons side by side.
Level 2 · Secondary
ink-0 fill · ink-900 text · rule border. At most one secondary alongside a primary. Used for non-blocking supporting actions. Smaller padding than primary. Same mono uppercase treatment.
Level 3 · Ghost
No border · underline only · ink-600 text. For disclosure actions: "expand," "view detail," "see all." Never alongside two buttons of higher levels — only when primary is the only button or secondary is already present.
Level 4 · Destructive / Escape
Text link only · no button chrome. Destructive actions (revoke, delete, withdraw) in s-hold ink. Escape actions (cancel, go back) in ink-500. Never a button. Never near a primary button. Always the lowest element in the action zone.

06

Implementation guidance · Claude Code · binding rules

zone structure · signal rules · language rules

These rules are binding on every surface built for the VitalCV progression arc. They are written as implementation directives — not preferences. Claude Code should treat any deviation as a bug to fix, not a judgment call.

Zone Structureevery surface · no exceptions
Zone A
always ink-900 fill or display-weight type · one primary signal · one sentence or number · no labels, no chips, no icons as the signal itself
Zone B
Body 400 13px · ink-700 · max 2 facts · no tables · no chips at body weight · inline prose only
Zone C
One .btn-primary · optional one .btn-ghost · two primary buttons side by side · disabled primary button — hide instead
Zone D
Ink-50 background · 1px dashed rule top · mono micro-type only · cards or panels in Zone D · flat row of key-value pairs only
Signal Rulesone per screen · competitive signals are bugs
Primary signal
must be a fact, not a label · "47 of 50 verified" not "Verification Status" · count or verdict or outcome · display-weight type (600, 20px+)
Conflict check
Before shipping any screen: identify the primary signal. If two elements compete for Zone A weight, one must be demoted. two display-weight elements on one screen
Empty states
Zone A is never empty. If no data: "Verification hasn't started yet." If loading: "Checking sources — results in a moment." One sentence. No spinners in Zone A.
Error states
Zone A carries the error in plain English. Zone B carries what the reviewer should do. stack traces or error codes in Zone A · red fills on Zone A
Progressive DisclosureTier 1 default · Tier 3 never default
Default tier
all surfaces default to Tier 1 · chain, run_id, source URLs hidden · expand via explicit intent (click "View detail" or "Audit trail")
Tier 3 access
Only on surfaces explicitly labeled "Audit" or "Forensic" · Tier 3 data in the default view of any operational surface
Expand pattern
Disclosure uses a ghost-level text link: "View claim detail ↓" · never a chevron icon · never a toggle switch · never a tab panel unless Tier 3 is the purpose of the surface
Language Rulesplain English · institutional audience · no engineering vocabulary
Audience
Write for a credentialing director or MSO compliance reviewer. Not for an engineer. If the sentence would confuse a non-technical reader, rewrite it.
Forbidden terms
cryptographic · blockchain · DID · VC 2.0 · OpenID4VCI · hash · anchor · smart contract · immutable · zero-knowledge — in body copy or Zone A/B
Permitted technical terms
run_id · checked_at · NPI · chain · replay — in Zone D and Tier 3 surfaces only · never in body prose
Alarm level
Match tone to severity. Degraded source: neutral, informational. Blocked claim: direct, factual. alarm language for non-blocking states · reassuring language for blocking states
Forbidden Patternsdesign bugs · not design choices
Dashboard clutter
equal-weight KPI card grids · four stats at the same visual weight · progress rings or doughnut charts · sparklines · trend arrows
Status overload
more than 3 status chips visible simultaneously · color fills for status · icons as primary status signals · blinking or pulsing status indicators (except the single op-bar dot)
Action overload
more than 3 actions visible simultaneously · two primary buttons · dropdown menus in Zone C · icon-only buttons without accessible labels
Engineering hierarchy
run_id in Zone A · chain strip in Zone A or B · source URLs in Zone A or B · error codes in Zone A · technical IDs in body prose
