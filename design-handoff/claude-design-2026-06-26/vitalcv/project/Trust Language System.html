§1
Three canonical concepts.
Every term in the workspace is a variant of one of these three words — or it should be removed. Compress ruthlessly. When in doubt, ask: is this a Record, Source, or Status?
Concept 01
Record
Replaces: chain, anchor, hash, provenance, immutability, block, merkle root, head
Concept 02
Source
Replaces: endpoint, ARCOS, TTL, degraded, polled, retry queue, epoch, sink
Concept 03
Status
Replaces: state, stage_flag, REVIEW_REQUIRED, ACTIVE_ANCHOR, chain_head, epoch_state
Operator test. Read the sentence aloud. If an operator who is not a developer would need to Google a word, replace it. The operator is an institutional onboarding coordinator — not an engineer, not a blockchain specialist.

§3
Trust-language hierarchy.
Five levels. The level governs where copy appears, how prominent it is, and what action it implies. Never escalate a level unnecessarily. Most screens should be Level 2 (Operational).
0
Silent
Nothing shown.
Everything is operating normally. The most common and correct state — absence of signal IS the signal.
No indicator · no copy · no color · no badge
1
Ambient
Records are current. Sources live.
Background assurance for operators who want confirmation. Sidebar only. De-emphasized. Never in the main content area.
Sidebar sources section · --ink-400 text · 8.5px mono · no color
2
Operational
7 of 10 verified.
Main stage content. Factual, declarative, past tense where complete. No interpretation. No reassurance needed. Just state.
Stage header title · 20px bold · --ink-900 · no color signal
3
Attention
DEA is checking again. Last result shown. No action needed.
Something to know, not necessarily to act on. Banner + sidebar indicator. Three parts: what happened · what's showing · what to do (usually nothing).
Attention notice bar · --watch amber · dashed border · dismiss available

DEA last responded 5 hours ago — last result is shown. Resuming automatically. No action needed.

Decision

Operator must act to advance. One dominant signal. Priority list with one action per item. Never called "error," "failure," or "alert."

§4
Realism boundaries.
Every visible value in the product belongs to one of four trust boundaries. Display and copy must match the boundary. Never present a projection as a measurement or an estimate as a confirmation. Bounded honesty is a feature, not a limitation.
Live
Real, now, from a source.
Data retrieved from a live source within the last check window. No label needed — this is the default and highest trust state.
Licensed and active
NPPES confirmed · 22 seconds ago
No disclosure tag. Absence of label = live and confirmed.
Last known
Real, but from a prior check.
Source not responding — showing the most recent valid result. Always name the source and the age. Never hide the gap.
Last result shown
DEA · from this morning · 5h ago
Dashed indicator on source bar. Age always shown. No false confirmation.
Estimate
Derived from real data, projected forward.
Calculated from pilot measurements. Always labeled as a projection. Never presented as a confirmed outcome or a guarantee.
Projection · labeled · not a measurement
Based on 10-clinician pilot · 28 days
Disclosure tag on every estimate. Copy must say "estimated" or "projected."
Pilot scope
True for this pilot only.
Valid for the bounded pilot scope — not a production claim. The word "pilot" must appear near any claim derived from pilot data.
10 clinicians · this pilot
Not a production deployment claim
Pilot badge on scope-bounded claims. Never imply production scale.

§8
Implementation guidance for Claude Code.
Rules for implementing this language system in the VitalCV codebase. Every rule has a rationale.
Copy grammar rules
G1
Stage titles use declarative past tense when complete. "7 of 10 verified." not "Verification in progress." Period at end. Always a complete sentence.
G2
Source issues are recoverable by default. "DEA is checking again" not "DEA ARCOS degraded." Reserve "not responding" only for extended outages (>4h).
G3
Timestamps are always human-readable. Use Intl.RelativeTimeFormat for age ("22 seconds ago"). Use Intl.DateTimeFormat for times ("2:31 PM"). Never expose UTC epoch or ISO 8601.
G4
Action-needed is always explicit. Every view states either "No action required" or names one specific action. Never leave the operator without orientation.
G5
Ownership chip governs copy tone. own-sys → passive/automatic. own-rev → active/direct. own-org → read-only/submitted. Never mix tones.
G6
Estimates are always labeled. Any projected or derived number requires "an estimated," "projected," or a disclosure label chip. No exceptions.
Navigation rules
N1
The sidebar arc IS the navigation. No top nav tabs. No hamburger. No breadcrumb trail. Each stage view is reachable from the arc and the attention queue only.
N2
Every view has one primary action and at most one ghost option. Use .btn-p for primary, .btn-g for ghost. No action = no button (system is handling).
N3
Back navigation is always a ghost link. "← Return to pilot" — never a full button. Never auto-redirect without user intent.
N4
The attention queue home view is the default landing. Operators should land on the ONE dominant signal ("3 clinicians need review") not a dashboard of metrics.
Trust boundary rules
T1
Live data has no label. Absence of label = confirmed, live, from source. Adding a "Live" badge would be redundant and inflationary.
T2
Last-known data shows source + age. Format: "[Source] · last result from [relative time]". Never hide the age. Never say "current" for stale data.
T3
Projections require disclosure tag. Use the .ib-lbl pattern: "Projection · labeled · not a measurement." Adjacent to every projected figure.
T4
Pilot scope claims are bounded. Say "these 10 clinicians" not "clinicians." Say "this pilot" not "in production." The scope boundary is a trust feature.
Attention queue algorithm
P1
Reviewer items with source issues — sorted by source age descending (oldest stale first). These are most time-sensitive.
P2
Reviewer items with results arrived — sorted by arrival time descending (most recent first). Ready for review.
P3
Reviewer items still running — sorted by elapsed time descending. Not urgent, but visible.
BG
System background items — shown below the fold in a muted "System is handling" section. No action button. Dashed dot indicator. Never in the numbered priority list.
