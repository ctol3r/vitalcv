Security architecture · What this system never accesses VCV-ARCH-001 · Permanent · Binding
01 PHI
ZERO
PHI
No patient identifiers, clinical dates, or health records cross this lane. Inputs are rejected programmatically by schema validation — not by policy promise. No exception path exists in the current architecture or any planned revision of it.
02 CRED
ZERO
Credentials
VitalCV holds no passwords or authentication secrets. Sign-in resolves exclusively through sovereign hospital identity providers (Okta, Azure AD, SAML 2.0). We do not see, store, issue, or rotate authentication data of any kind.
03 INTERP
ZERO
Re-Interpretation
Federal registries remain entirely authoritative. We trace and sign what the source returned; we never substitute independent judgment, amend the record, or certify beyond the registry response on file at time of issuance.

Component usage note

This band is designed to embed in the global app shell footer, or as a header block on any screen that handles clinician data. It carries no interactive state. Drop it above the <footer> or below the page h1 on compliance-sensitive routes. The dashed border variant signals "boundary." The compact variant fits in a 48px footer rail.
