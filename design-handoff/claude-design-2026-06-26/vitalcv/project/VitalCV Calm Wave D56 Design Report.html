02

Executive summary

VitalCV's core promise is reusable, source-backed clinician readiness. The product is strong at the truth-state register (D55) and at honest passport degradation (PR #419). What it does not yet have is a calm front door: today, a first-time visitor lands among four overlapping CTAs (Check Readiness, Start a Pilot, Sign In, Contact) and cannot tell whether to type an NPI, ask for a demo, or sign up — and an unauthenticated user has no idea why sign-in would help them. This wave fixes the front door without touching the back. We introduce one NPI-first entry point, role-routed sign-up that explains why, a Proof Continuity Rail that makes interoperability legible across Passport, Trust, Demo and Employer views, a zenlike UI doctrine that retires fake activity and shame language, and degraded-state copy that protects clinicians when sources fail. Every CTA answers the single question "what do I do next?"; every state reduces anxiety; no surface implies final credentialing.

07

Zenlike UI doctrine

CONCRETE · NOT VIBES

Rules, not adjectives. Each is testable in design QA.

VISUAL STYLE
Background is --paper #f4f2ec. Foreground rule uses the --ink scale only. No gradients in marketing or product surfaces.
One accent per state, never decorative. Reds (--p0) are reserved for actual adverse or blocking signals — never for "unavailable" or "not connected".
One primary action per surface. Secondary actions are btn.ghost or btn.muted. Tertiary actions are mono-cased text links.
Type stack: Geist for prose, Geist Mono for state, identifiers, eyebrows. No third family.
Density is earned with hierarchy, not stripped with bigger margins. Tables and registers are first-class.
No decorative crypto visuals. No looping pulses. No "live" ticker animations. No SaaS confetti.
INTERACTION STYLE
NPI-first. The fastest path to value on / is typing 10 digits and pressing return.
One decision per screen. If a screen presents two, the second is a quiet secondary, not a peer.
Role-aware progression: post-login destination is computed from the role tile, not from a generic dashboard.
Every CTA answers "what do I do next?" A button labeled with a noun ("Passport") is a destination; a button labeled with a verb ("Check readiness") is an action — never blend.
Unknown / unavailable feels operational, not personal. Copy never grades the clinician.
No shame language. No "incomplete", "missing", "failed verification". Use "needs institution review" or "not connected in this build".
MOTION
All transitions 280–420ms, default 320ms. Easing: cubic-bezier(.2,.7,.2,1).
Permitted motion: fade, slide ≤8px, opacity, single-shot. No looping animations on idle surfaces.
"Live" indicators only when tied to a real event in the last 60s. Otherwise show a timestamp.
Loading state is a skeleton lane with the source name visible. No global spinners, no shimmer larger than the affected cell.
No fake activity tickers. No counters that increment without a source event. No animated checkmarks for things that did not just happen.
INFORMATION HIERARCHY
1. What happened. One sentence at the top of every readiness surface.
2. What it means. A single line per lane in the Proof Continuity Rail.
3. What is still needed. Lane-level CTA, never page-level alarm.
4. What to do next. One primary action below the rail.
5. Proof details only if expanded. Inspect drawer carries runId, lineageKey, kid, attestation boundary.
No information that fails the "would a clinician want to read this?" test on the primary surface.
