Readiness score display guidance
(1) Always label. The numeric value sits under Readiness status · preliminary — never bare. (2) Never use as a headline. The score is a sidebar, not a hero number. (3) Never render as a precise canonical score. The bar uses a dashed/repeating-pattern fill, not a solid colored progress fill, so it visually reads as "fraction of connected lanes" — not "percent verified". (4) Caption is mandatory. "Reflects connected source lanes only. Not a credential score." cannot be hidden behind a tooltip alone. (5) Tooltip on hover explains derivation in one sentence: "20 / 100 = identity lane source-confirmed · 3 lanes pending source connection or institution review."
What "Partial" does NOT mean
Partial does not mean rejected, suspended, or flagged. It does not mean the clinician failed a check. It does not mean an exclusion was found. It does not mean an enrollment lapsed. It means: fewer than all credentialing lanes have produced source-confirmed evidence today. Some are not connected. Some need institution review. None of the unsatisfied lanes have produced a negative finding.

Phase 08

Loading & error copy — strict rules

"Checking in the background" is gated

"Checking in the background" is the most dangerous string on the Passport page — it implies a check is alive when the lane has already failed, is not connected, or is access-gated. This phase pins its allowed envelope and bans every misleading pairing.

Rule 1 · When loading copy is allowed
"Checking in the background" may appear on a lane only if all three are true:
(1) a real async job for that lane is currently active in the worker pool;
(2) the SSE / polling channel for that lane is still open;
(3) no terminal state (SOURCE_CONFIRMED, CHECKED, TEMPORARILY_UNAVAILABLE, DATASET_PENDING, SOURCE_NOT_CONNECTED, ACCESS_REQUIRED, STALE, REVIEW_REQUIRED) has been received for that lane in this session.

If any of (1)/(2)/(3) is false, the lane must flip to its terminal-state row immediately — same render frame.

Rule 3 · Prohibited copy pairings
Never co-render "Checking in the background" alongside
"Unavailable" — terminal error already received; loading copy is a lie.

Why these specific pairings are P0
The string "Checking in the background → Unavailable" implies a real check was attempted and timed out. For OIG/LEIE and PECOS in this build, no check was ever attempted because the source is not connected. The current copy converts a build limitation into the appearance of a federal-source failure — which, in a PearX or buyer review, reads as "this product cannot read federal data" instead of "this product has not yet wired these sources". The two are very different stories. Phase 08 forbids the first story unless it is literally true.
