## Verdict: 60% Operational, 40% Demo Theater

The core review flow (ReviewClient.tsx) and its evidence/scoring components are tight — data-dense, token-consistent, and appropriately austere. But a ring of surrounding employer components still carry sandbox-era aesthetics: fake terminal outputs, hardcoded source lists with unintegrated sources, staggered motion animations, and consumer-grade visual flourishes that undermine audit credibility.

## Component-by-Component Assessment

### ScoreExplainabilityBlock.tsx — PASS (Stripe-grade)

This is the strongest component in the employer surface. Three-column breakdown (Helping / Hurting / Ceiling effects) with `+N` / `-N` impact badges. Monospaced tabular numbers. Proper disclaimer footer. Uses `vt-*` tokens and `white/[0.02]` transparency layers consistently. The `text-[10px] uppercase tracking-[0.2em]` section headers read like Bloomberg terminal labels.

**No changes needed.** This is the reference component for how everything else should look.

### TrustStateCard.tsx — PASS (minor)

Clean data card. Accessibility is correct (`aria-labelledby`, tooltip providers, `role="img"` on status dots). Blocking reasons render in a red alert box with enumerated items. `font-mono` for band labels and dates.

**One issue:** Uses `slate-*` Tailwind defaults instead of `vt-*` design tokens. This means it renders in light mode when the ops shell is dark-themed. Either align to the ops dark palette or confirm this component only appears in the light-themed employer review context.

### EvidenceViewer.tsx — PASS (with one nit)

Dense, functional, properly operational. Sort/group controls. Expandable evidence rows with provenance chain, freshness markers, source quality ratings, corroboration counts. Uses `vt-*` CSS custom properties throughout. `confidenceBar()` renders a minimal progress bar — no animation, just `transition-all`, which is acceptable.

**Nit (lines 326–331):** "Pin to storyline" and "Flag for re-check" action buttons have **no onClick handlers**. They render as interactive elements with hover states (`hover:border-cyan-400/40`) but do nothing. Either wire them up or remove them — dead interactive elements in an audit-grade surface signal incompleteness.

### OpsLoadingScreen.tsx — PASS

Pure skeleton blocks using `vt-*` tokens. No spinners, no generative text, no pulse animation. This is correct loading behavior for an operational tool.

### detail-loading.tsx — PASS (marginal)

Uses `animate-pulse` on skeleton blocks. This is Tailwind's built-in pulse — subtle and standard. Acceptable, but worth noting: Palantir's Foundry uses **no pulse animation on loading skeletons**, preferring static grey blocks. Consider removing `animate-pulse` for maximum austerity.

## RED FLAGS — Components That Need Surgery

### VerifierConfidencePanel.tsx — FAIL (P0, demo theater)

This is the single worst offender in the employer surface. Multiple doctrine violations:

**1. Hardcoded DEA as a verification source (lines 85–89)**
```tsx
{ name: 'DEA Registration', status: 'Verified', icon: Activity },
```
DEA is **not integrated**. The copy prohibition list explicitly states: "NEVER add to UI or copy (not integrated): NPDB, DEA, ABMS, SAM.gov, Doximity." This is a P0 compliance violation.

**2. Fake terminal aesthetic (lines 109–127)**
A dark `bg-slate-900` box with green monospace text showing:
- `# Generating cryptographic proof...`
- `> Hash: 0x8f2a...c9d4`
- `> Timestamps synchronized.`
- Hardcoded fake signature strings: `sig_nppes_9f82kd01`, `sig_board_ca_09214`, `sig_dea_xz91823k`
- A "Download Full Audit Proof (.zip)" button that appears interactive but has no real handler — it's a `<div>` with `cursor-pointer`

This is textbook "generic AI playground." It communicates "we have crypto magic" without actually representing any real system state. An employer compliance officer seeing this will immediately question the system's legitimacy.

**3. Hardcoded latency default (line 22)**
`latencyMs = 142` — a default prop that looks like a real measurement but is a fabricated number. If you're going to show verification latency, it must come from actual API timing data.

**4. Consumer-grade styling**
`rounded-2xl shadow-sm`, `font-serif` for the readiness score, `hover:bg-slate-50 transition-colors` on the expand trigger. This reads like a fintech consumer app, not an audit instrument.

**Recommendation:** Delete this component entirely and replace with a data row in ReviewClient that shows actual verification artifact metadata from the passport response.

### AuditTerminal.tsx — FAIL (P1, unnecessary animation)

The audit log entries use `framer-motion` staggered reveals:
```tsx
variants={{ hidden: {}, visible: { transition: { staggerChildren: 0.15 } } }}
// Each entry: hidden: { opacity: 0, x: -8 }, visible: { opacity: 1, x: 0 }
```

This means audit log lines slide in one-by-one with 150ms delays. In an operational context, this is wrong. When an employer opens the audit trail, the data should be **there**, not performing. Staggered animation says "look how cool this is." Instant render says "this is your data."

**Fix:** Remove all `motion.*` wrappers. Render the `<ol>` and `<li>` elements as plain HTML. The dark monospace aesthetic is fine — just strip the animation.

### EmployerReviewDashboard.tsx — CONDITIONAL PASS (P2, minor motion)

Uses `motion.div` on packet list items (lines 262–265):
```tsx
<motion.div key={packet.npi} initial={{ opacity: 0 }} animate={{ opacity: 1 }}>
```

Fade-in on list items is a consumer pattern. In an operational dashboard, items should appear instantly. The filter/sort interaction is otherwise well-structured with proper `font-mono`, uppercase tracking labels, and clean select inputs.

**Fix:** Replace `motion.div` with plain `div`. The `heading text-3xl font-bold` on line 127 is also too consumer-heavy — change to `text-xl font-semibold tracking-tight` or use `heading-lg` from the typography system.

### TrustStateResultCard.tsx — CONDITIONAL PASS (P2, over-designed)

This component has strong data architecture (trust level, readiness score, artifact count) but wraps it in too much visual decoration:

- `rounded-3xl` outer container with a `p-1` border hack creating a double-card effect
- `rounded-[1.35rem]` inner container — fractional rounding screams "designer fiddling"
- `text-3xl sm:text-4xl font-light` for the status label — "Ready" rendered at 36px is theatrical, not operational
- `AnimatePresence` + `motion.div` for the artifact list expand/collapse with `duration: 0.3` ease
- `transition-all duration-300` on the outer container

**Fixes:**
- Reduce status label to `text-lg font-semibold`
- Replace `rounded-3xl` / `rounded-[1.35rem]` with `rounded-xl` (consistent with OpsCard)
- Replace `AnimatePresence`/`motion.div` with CSS `max-height` transition or instant toggle
- Remove the `p-1` double-border trick — use a single `border` with appropriate color

## Systemic Issues

### 1. framer-motion proliferation in employer components

8 employer components import framer-motion. The review flow itself (ReviewClient.tsx) imports **zero**. This mismatch suggests the employer components were built in a different design sprint with consumer-grade UX assumptions.

**Rule:** Strip `framer-motion` from all employer and trust-state components. The only acceptable motion in an audit-ready surface is CSS `transition` on interactive state changes (hover, focus, expand/collapse) with `duration` ≤ 150ms.

### 2. Mixed theme systems

TrustStateCard uses `slate-*` / `bg-white` (light Tailwind). EvidenceViewer uses `var(--vt-*)` (dark ops tokens). ScoreExplainabilityBlock uses `white/[0.02]` transparency (dark). VerifierConfidencePanel uses `bg-white border-slate-200` (light). TrustStateResultCard hedges both with `dark:` variants.

**Rule:** The employer review surface is an operational tool. Pick one system — `vt-*` ops tokens — and enforce it. Remove all raw `slate-*` / `bg-white` overrides.

### 3. Dead interactive elements

EvidenceViewer has "Pin to storyline" and "Flag for re-check" buttons with no handlers. VerifierConfidencePanel has a "Download Full Audit Proof" div that does nothing. These create the impression of a prototype, not a production system.

**Rule:** If a button does nothing, it doesn't ship. Remove or wire up.

## Reference: What "100% Operational" Looks Like

The target aesthetic already exists in this codebase. **ScoreExplainabilityBlock** and **EvidenceViewer** are the reference implementations:

- `text-[10px] uppercase tracking-[0.18em]` for section labels
- `tabular-nums` on all numeric values
- `font-mono` for IDs, hashes, timestamps
- `var(--vt-*)` custom properties for all colors
- `rounded-xl` or `rounded-lg` (never `rounded-2xl` or `rounded-3xl`)
- Borders: `border-white/6` or `border-[var(--vt-border)]`
- Zero framer-motion. Zero staggered reveals. Zero fade-ins.
- Empty states that say exactly what's missing and what to do next

Every component in the employer review flow should converge on this standard.
