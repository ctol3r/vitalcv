# SYSTEM COMPLETION PRIORITY PLAN

This execution plan translates the `SYSTEM_COMPLETION_GAP_MAP.md` into an ordered strike sequence. Every wave is designed to unblock the next, focusing first on survival loops, then trust clarity, and finally network optimization.

---

### SUB-WAVE A: CORE & TRUST FOUNDATION (The "Why")
*If the trust engine isn't believable, nothing else matters.*
1. **Core Wedge (System 1):** Stabilize the NPI → readiness pipeline. Implement the missing cross-source divergence resolution logic so scoring is deterministic and explainable. 
2. **Trust / Explainability (System 4):** Expose the graph traversals. Wire the `capsuleEngine` (Decision Capsules API) to Postgres and implement the Trust Timeline & Evidence Explorer. This proves the score.

### SUB-WAVE B: EMPLOYER & REUSE LOOPS (The "Value")
*If employers can't confidently act or reuse the data, the network stalls.*
3. **Employer Loop (System 3):** Productize the Employer Review surface. Un-gate the `INSTANT_OFFERS` service and wire the `simulationMachine` (Trust Simulation Engine) for live revenue/blast radius modeling.
4. **Snapshot Reuse (System 6):** Standardize the `ApplyPayload` in the `embed-sdk`. Build the webhook receiver and scaffold the ATS integration adapters (Workday) so the "Apply with VitalCV" widget works end-to-end.

### SUB-WAVE C: CLINICIAN & MATCHA LOOPS (The "Flywheel")
*If clinicians hit dead ends, liquidity dies.*
5. **Matcha Loop (System 5):** Un-gate `MATCHA_V2`. Wire the scoring logic to the actual readiness engine outputs and connect to live opportunity registries. Fix dead job clicks.
6. **Clinician Loop (System 2):** Introduce the GME-aware (resident/fellow) onboarding wedge. Ensure the `/me` dashboard explicitly lists readiness blockers and deterministic next actions.

### SUB-WAVE D: METRICS, MARKETING, & API (The "Scale")
*Exposing the system to the outside world.*
7. **Signal + Learning (System 7):** Ensure SEAL Advisory Pipeline (`sealEventCapture.ts`) is tracking all application loops, decisions, and blocker resolutions.
8. **Ops / Control Plane (System 10):** Build the Employer Capacity Dashboard (SEPQ, ISV metrics) and surface divergence metrics in the `/ops` control plane.
9. **Developer / API (System 9):** Finalize API key management and OID4VP webhook dispatchers.
10. **Marketing Surface (System 8):** Finalize the marketing truth-purge (Wave 0 release gate), ensuring the homepage clearly previews the trust output without overpromising.

---
*Execution must proceed strictly down this list. Each step is tracked against the Phase 4 Validation criteria.*
